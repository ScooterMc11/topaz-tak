# AGENTS.md — Topaz Tak

A high-performance engine for the board game [Tak](https://en.wikipedia.org/wiki/Tak_(game)),
written in Rust. As of late 2025 it is among the strongest Tak engines on consumer hardware,
competitive with GPU-based neural engines (e.g. TakZero) at fast time controls. The engine is
primarily optimized for **6x6 Tak with 2 komi for black**; 5x5 and 7x7 are playable but use
weaker search/eval.

This file orients both humans and future Claude sessions. See also `README.md` for the
user-facing pitch and feature checklist.

> **Branch note:** this is the experimental local branch `double-black-stack` (not pushed). It layers
> a first-player-advantage rule change plus self-play / NNUE-training / balance / SPRT tooling on top of
> the base engine — see the "Black-stack experiment & self-play tooling" section below. On `main` the
> engine is plain 6x6 + komi with none of that.

## Quick facts

- **Language / build:** Rust 2021, Cargo. `cargo build --release` (release profile uses `lto = true`
  and keeps `debug = true` for profiling).
- **Binary:** `topaz` (`src/topaz.rs`), requires the `cli` feature (on by default).
- **Library crate:** `topaz_tak` (`src/lib.rs`).
- **Cargo features** (`Cargo.toml`): `default = ["random", "cli", "evaluation"]`.
  - `evaluation` — search + NNUE eval + transposition table modules.
  - `cli` — interactive binary deps (termtree, colorful, getopts, telnet, dotenv) + opening book.
  - `random` — RNG deps for noise / book sampling.
- **⚠️ Required external file:** the NNUE network `src/quantised.bin` is **gitignored**
  (`.gitignore` excludes `src/*.bin`) and must be downloaded separately (see README's Google
  Drive link). It is `include_bytes!`-embedded at compile time in
  [src/eval/incremental.rs](src/eval/incremental.rs) (`static NNUE`), so **the build fails without
  it.** If a build complains about a missing `quantised.bin`, that's why.

## Running the binary

Default (no args / stdin `tei`): launches **TEI** mode (Tak Engine Interface, UCI-like) for use
with GUIs / [ptn.ninja](https://ptn.ninja/). Other subcommands are dispatched in `main()` of
[src/topaz.rs](src/topaz.rs):

- `topaz analyze <tps>` — analyze a single position (also accepts saved-position aliases and PTN files).
- `topaz tinue <tps>` — proof-number Tinue (forced-win) solver; flags `-d` defender, `-n` node limit, `-i` interactive.
- `topaz selfplay <tps>` — self-play a game out.
- `topaz playtak` — connect to playtak.com server (telnet; limited support).
- `topaz white|black` / stdin `play white|black` — command-line play.

`SAVED_TPS` (top of `topaz.rs`) holds named test positions (`alion1`, `midgame1`, `endgame1`, …)
usable wherever a TPS string is expected.

## Source map

Sizes are rough; line counts in parentheses for the meaty files.

### Core library — `src/lib.rs` (332)
Crate root and shared types: `Position` trait, `TakGame` enum (`Standard5/6/7` dispatch), `Color`,
`GameResult`, `TimeBank`, `TeiGo`/`TeiCommand` (protocol parsing), `GameInitializer`, `perft`.

### Board — `src/board.rs` (929) + `src/board/`
Board representation and rules. `TakBoard` trait is the central abstraction; concrete boards
`Board5`/`Board6`/`Board7` are generated by the `board_impl!` macro.
- `board/bitboard.rs` (878) — `Bitboard` trait + per-size bitboard types, road detection, etc.
- `board/stack.rs` (498) — `Stack` (a tower of pieces on one tile) and its bit-packed encoding.
- `board/piece.rs` (124) — `Piece` enum (flat/wall/cap × color).
- `board/zobrist.rs` (227) — Zobrist hashing; `zobrist.table` is the precomputed key data.

### Move generation — `src/move_gen.rs` (900) + `src/move_gen/`
`generate_all_moves` (placements + stack spreads). `GameMove` is a `#[repr(transparent)]` `u32`
with a documented bit layout (src tile / direction / pickup count / spread / wall-smash / placement
piece — see the doc comment at `GameMove`). `RevGameMove` carries undo info.
- `move_gen/move_order.rs` (794) — move ordering + history heuristics: `HistoryMoves`,
  `CaptureHistory`, `PlaceHistory`, `KillerMoves`, `CounterMoves`, `CorrHist` (static-eval
  correction history), `SmartMoveBuffer`, `ScoredMove`.
- `move_gen/ptn.rs` (276) — PTN (Portable Tak Notation) parsing/printing of moves.
- `move_gen/magic.rs` (320) — magic-bitboard experiments (currently `mod` commented out in move_gen.rs).

### Evaluation — `src/eval.rs` (1066) + `src/eval/` (gated behind `evaluation`)
`Evaluator` trait (`evaluate`, `set_tempo_offset`). The production evaluator is **`NNUE6`**, an
efficiently-updatable neural net for Board6.
- `eval/incremental.rs` (623) — the NNUE: `Network` layout, quantization consts (`HIDDEN_SIZE=512`,
  `QA`/`QB`, `SCALE`), `BoardData`/`PieceSquare`/`ValidPiece`, the embedded `NNUE` weights, and
  incremental accumulator updates.
- `eval/smooth.rs` — currently empty (0 lines).
- Legacy/handcrafted evaluators (`Weights5`, `Weights6`, `SmoothWeights6`, `PST6`) still exist for
  smaller sizes / experiments; the various `*.table` and `vals_small.txt` files are their weight data.

### Search — `src/search.rs` (955) + `src/search/` (gated behind `evaluation`)
Negamax alpha-beta. Tunable constants live at the top of `search.rs`. Implements: null-move pruning,
PVS, late move reductions, forward/reverse futility pruning, aspiration windows, internal iterative
deepening, history orderings, correction history, LazySMP multithreading (`multi_search`), and
limited MultiPV. Entry points: `search`, `multi_search`.
- `search/util.rs` (475) — `SearchInfo` (per-search state/config builder), `SearchOutcome`,
  `SearchStats`, `SearchHyper` (tunable hyperparameters), `HashHistory`.
- `search/book.rs` (54) — opening book via weighted trie (`cli` only); loaded from a `.book` file.

### Proof search — `src/proof.rs` (780)
`TinueSearch` — a PN (proof-number) search solver for "Tinue" (forced road-win) positions.
Independent of the eval; works on all board sizes.

### Transposition table — `src/transposition_table.rs` (344)
`HashTable` / `HashEntry` / `ScoreCutoff`. Lock-free atomic table shared across LazySMP threads
(uses `bytemuck` zeroable atomics).

### Benchmarks — `benches/benchmark.rs` (103)
Criterion harness (`cargo bench`); currently benches tak-threat detection over a position set.

### Experiment tooling — `src/datagen.rs`, `src/balance.rs`, `src/openings.rs`
Self-play data generation, balance assessment, and opening-book generation for the
`double-black-stack` branch (all gated behind `evaluation` + `random`). Detailed in the
"Black-stack experiment & self-play tooling" section below.

## Black-stack experiment & self-play tooling

Everything in this section is specific to the `double-black-stack` branch.

### The rule
White's first-move advantage is offset not by komi but by a **"double black stack" opening**: White's
first move places a **2-high stack of black flats** (both drawn from Black's reserve) instead of the
standard single swapped flat, played at **komi 0**. The rule lives in the source, so **every build
plays it** — only the embedded net differs.

- **Where it lives:** move generation forces it at `board.move_num() == 1` for White in
  `generate_all_place_moves` ([move_gen.rs](src/move_gen.rs)) — a flat placement encoded with
  `number() == 2`. The double placement / reserve bookkeeping is applied in `do_move` /
  `reverse_move` / `legal_move` ([board.rs](src/board.rs)). PTN prints/parses it as `2<square>`
  (e.g. `2a1`) in [move_gen/ptn.rs](src/move_gen/ptn.rs).
- **Key invariant:** the rule only fires at `move_num() == 1`. From a TPS loaded at `move_num >= 2`
  the engine plays **standard Tak**. This is what makes the SPRT/balance book approach work.

### Nets and per-net builds
Two reference nets live in `src/`, each exactly **1,053,760 bytes** (`size_of::<Network>()`):
`quantised-2-komi.bin` (original standard net) and `quantised-black-stack-iter-2.bin` (variant net).
`src/quantised.bin` is the gitignored working copy that gets `include_bytes!`-embedded. **To build a
specific net:** `cp <net>.bin src/quantised.bin && touch src/eval/incremental.rs && cargo build
--release`, then save the binary under a distinct name (the `touch` forces re-embed if cargo misses
the `.bin` change).

### Self-play subcommands (behind `evaluation` + `random`)
- `topaz datagen` / `checkdata` / `trimdata` ([datagen.rs](src/datagen.rs)) — generate / validate /
  trim TAK6 binpack self-play data for NNUE training. Trainer is the **external** `bulletTrainer/bullet`
  (sibling of this repo); `new_rng()` seeds from OS entropy.
- `topaz balance` ([balance.rs](src/balance.rs)) — self-play balance (same net both sides): White vs
  Black win %, road/flat win types, 95% CI. Flags: `-r` random flat opening plies (default; opening
  randomness is flats-only via `do_random_flat_move`), `--book <tps>` (play each book position once,
  deterministically — book size = game count), `--komi <half_komi>` (0 default; **4 = 2 komi**),
  `--archetypes` (generate the black-stack book internally and break results down per opening
  archetype), `--standard` (with `--archetypes`: standard openings instead of black-stack),
  `--weights a,b,..` (per-archetype weighting), `--ptnout FILE` + `--ptn-limit N` (dump the first N
  played games as replayable PTN with a `[TPS]` tag).
- `topaz openings` ([openings.rs](src/openings.rs)) — emit a **TPS** opening book (+ a parallel
  human-readable PTN book) of D4-deduped, 6-ply black-stack openings from 5 archetypes (diagonal /
  adjacent corners, hug, gap-hug, center-stack). `--standard` switches to single-flat (standard)
  openings with 3 archetypes (for the 2-komi comparison). Exposes `openings::generate[_weighted]`,
  reused by `balance --archetypes`.

### Strength testing via racetrack (sibling repo `../racetrack`)
Racetrack is a TEI match runner that **arbitrates with stock `tiltak` (standard rules)** — it rejects
the `2xx` opening and would desync on it. So the opening book must be **TPS positions past the opening**
(`--book-format tps`), never a move-list. Both engine builds embed the same rule (never triggered,
since games start at `move_num >= 2`) and differ only in the embedded net. Typical SPRT:
`racetrack -s 6 --komi 0 --book <tps> --book-format tps --format sprt --sprt elo0=0 elo1=5
alpha=0.05 beta=0.05 --engine path=<net-A> --engine path=<net-B> --all-engines tc=3+0.08`. Komi is
set only via `--komi` (passing `option.HalfKomi=` panics racetrack). Result (2026-06): the black-stack
net is **~+117 Elo** over the 2-komi net at the variant (SPRT passed).

## Conventions & gotchas

- **Board size dispatch:** most engine code is generic over `TakBoard`; `TakGame` matches at the
  top level. Much of the binary's `Standard5/7` arms are `todo!()` — 6x6 is the real target.
- **Tempo / side-to-move:** NNUE eval applies a `tempo_offset` on odd plies; eval scores are from
  the side-to-move perspective (negamax).
- **TPS / PTN:** positions are TPS strings; moves are PTN. `try_from_tps` infers size from `/` count.
- **Tests** are inline `#[cfg(test)] mod test` blocks (e.g. in `search/book.rs`). Run with
  `cargo test`. `perft` is the move-gen correctness check.
- **Tuning:** `const TUNING` in `topaz.rs` and `SearchHyper` gate automated parameter tuning;
  many search constants are hand-commented with tuning notes — preserve those comments when editing.
- The codebase has substantial commented-out exploratory code (esp. in `topaz.rs` `analyze`). It is
  intentional scratch space, not dead code to clean up unasked.
